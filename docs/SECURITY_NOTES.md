# セキュリティ上の前提・制約

このリポジトリは上流Krokiの非公式ビルド構成です。脆弱性の継続的な修正や安全性を保証しません。公開判断と未検証事項の分類は[READINESS.md](READINESS.md)を正本とします。

## 検査条件

初回のTrivy検査は次の条件でした。

```text
--severity HIGH,CRITICAL --ignore-unfixed
```

これは「重大度がHIGH/CRITICALで、修正版が存在すると判断されたもの」を表示する条件です。
LOW/MEDIUM、修正版未提供、検出漏れ、攻撃到達可能性の評価は含みません。
現在の`scan.sh`は既定で全重大度を検査し、上記の条件は追加オプションとして指定します。
スキャンは最新の脆弱性データベースで都度実行してください。
正式な軽量化版の検査ではMEDIUM 98件とLOW 80件が残っています。
修正版ありHIGH/CRITICALが0件であることを、すべての脆弱性が解消したという判断に使わないでください。

## Javaと証明書

初回にJava 21.0.13+9を使い、`java -version`とJavaの`cacerts`を確認しました。`emSign Root CA - G1`の存在を確認していますが、eMudhra関連の名前を持つ証明書をすべて削除する運用にはしていません。信頼ストアの更新要否は、その時点のベンダーアドバイザリと対象証明書のフィンガープリントで判断してください。

## イメージレイヤー

本構成は公式Krokiイメージをベースに、Javaディレクトリ、Kroki JAR、D2、Goatを差し替えます。
フラット化前のイメージでは、削除や上書きの対象が下位レイヤーに残ります。
`build.sh`は開発用パッケージを除去した後、現在のファイルシステムを`docker export/import`で1レイヤーへまとめます。
元のレイヤー履歴、ビルド由来のattestation、署名は引き継ぎません。
生成した最終イメージを検査対象にしてください。

フラット化は上流イメージ内の全ソフトウェアを最新ソースから再ビルドする処理ではありません。
APTの自動削除候補を一括削除せず、実証済みの5パッケージとその依存削除に範囲を限定します。

[Docker export](https://docs.docker.com/reference/cli/docker/container/export/)はボリューム内容を出力しません。
本スクリプトはVolumesを持つイメージを拒否します。
[Docker import](https://docs.docker.com/reference/cli/docker/image/import/)の設定復元を使用し、元イメージの`Config`との一致を検査します。
Healthcheckやその他の未対応設定があれば、無視せず処理を中止します。

## ネットワークと実行

- 公開ポートは`127.0.0.1:8000:8000`などのループバックに限定する例を使います。WSLやOSのファイアウォール構成により実際の到達範囲は異なります。
- `KROKI_SAFE_MODE=secure`を維持してください。既知CVEの代替対策にはなりません。
- TrivyのDockerソケットマウントは`:ro`でもAPI操作権限を強く制限できません。信頼したイメージだけ使用し、CIでは権限を絞った代替も検討してください。
- 新しい版を本番利用する前に、変換形式ごとの試験、ログ、動作上の互換性を確認してください。

## 未対応・未検証事項

公開判断、既知制約、将来対応の分類は[READINESS.md](READINESS.md)に集約しています。Mermaidの補助コンテナはこの構成に含まず、追加する場合は独立した脆弱性検査と通信・描画試験を必要とします。
