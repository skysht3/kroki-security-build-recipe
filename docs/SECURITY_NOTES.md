# セキュリティ上の前提・制約

## 上流修正と独自差分

0.37.1にはD2、TikZ、Bytefieldの対策が入っています。[上流リリース](https://github.com/yuzutech/kroki/releases/tag/v0.37.1)

D2の対策はKroki側とD2バイナリ側を組み合わせて動作します。KrokiがSECURE/SAFEで渡す制限を解釈できるように、自前D2には固定したKrokiソースから上流パッチを取り込みます。D2本体のバージョンだけでパッチの有無を判断しないでください。[D2の勧告](https://github.com/yuzutech/kroki/security/advisories/GHSA-w5wj-qr95-xm33)

JARはGuavaのみを明示的に更新します。Java実行環境とGoatは公式イメージから継承します。証明書ストアを独自に差し替える処理はありません。

## 検査

`scripts/scan.sh` は既定で全重大度を検査します。`--severity HIGH,CRITICAL --ignore-unfixed --exit-code 1` は、修正版があるHIGH/CRITICALの検出を判定する追加条件です。未修正、低い重大度、検出漏れ、実際の到達可能性は別に扱います。Dockerソケットは `:ro` でも強い権限を持つため、承認済みのTrivyイメージを指定してください。

イメージはレイヤーを保持します。差し替え前のファイルは下位レイヤーに残るため、検出されたファイルのパスと、実行時に見える依存の版を照合してください。旧版のフラット化スクリプトは既定ビルドで使いません。フラット化は脆弱性の修正そのものではなく、実行すると上流のレイヤー来歴も引き継ぎません。

## 運用

- ポートはループバックに限定し、`KROKI_SAFE_MODE=secure` を維持します。実際の到達範囲はWSL・Docker・OSの設定でも確認してください。
- SECUREは更新の代替ではありません。信頼できない図を外部から受け付ける構成は、このレシピの検証対象外です。
- SVGをブラウザで表示すると、外部リンクの扱いは閲覧側の設定にも依存します。サーバー側で取得しないことと、閲覧側で取得しないことは別です。
